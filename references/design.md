# 设计规范与编辑原则

## 视觉来源

本设计改编自 YUANZL 的 `Endfield-PPT-Template`，参考其推荐的 `endfield_bilingual_canva_template_optimized_v6.html`。色彩以该 HTML 实际 CSS 为准，避免混用上游较早文档中的其他黄色。授权与改编记录见 [NOTICE.md](NOTICE.md)。

| 元素 | 默认建议 |
|---|---|
| 画布 | 16:9；左右安全边距约为宽度的 5%–6% |
| 浅底 | `#F3F4F1` |
| 深底 | `#111210` |
| 主文字／深色内容框 | `#1B1C1A` |
| 浅色内容框 | `#ECEEEC` |
| 强调黄 | `#F4F600` |
| 风险或失败强调 | `#E85B2A`，仅在语义确实需要时使用 |
| 浅底次要文字／分隔线 | `#555B57` / `#8F9691` |
| 深底主文字／次要文字 | `#F4F3EE` / `#D0D3CF` |
| 形状 | 直角框、细线、克制的低透明度网格；默认不使用卡片投影 |

中文优先选本机已有且能正确显示的字体。生成器默认使用 Windows 常见的 Microsoft YaHei；Linux 可将 `fonts.cn` 设置为实际已安装的 Noto Sans CJK SC，macOS 可按本机情况选择 PingFang SC。英文与编号可用窄体或等宽字体，但不应比中文结论更醒目。字体可用性与字体嵌入是两回事；不要假定接收者拥有同样字体。

可从标题 30–36 pt、正文 18–24 pt、来源及页脚 11–14 pt 开始。封面可用更大标题。这些是排版起点，不是强制配额；以实际投影、阅读距离和最终渲染为准。不要为塞入长文而持续缩小正文。

## 主次与适度密度

每页先回答“观众离开这一页应记住什么”，再选择最能说明它的结构。标题给出主题或判断，图表呈现关系，少量支持文字说明条件；备注承接论证过程。

- **封面**：一个主题、简短副标题、必要身份或日期。姓名、成员数量和元数据以用户输入为准。
- **比较**：并列展示相同维度；没有证据证明优劣时给予对称视觉待遇，不用颜色暗示胜负。
- **流程与架构**：动作、角色、输入输出和反馈分开；不要把组件清单误画成严格的执行顺序。
- **表格**：用于同维度比较、状态与依据、问题与措施等。每格保持短语或短句；明显复杂的单元格应拆解，而不是压缩字号。
- **循环**：同时表达正常推进和返工方向，说明什么触发返回。圆环不是所有主题的默认布局。
- **展望与讨论**：区分已有结果、待验证变化和后续阶段。讨论题应涉及真实取舍，例如范围、风险、资源或证据门槛。

常见页面可以用一个主要图解加 2–4 条支持信息，也可以用少量表格行完成论证。不要把任何固定字数当作验收条件：把必要定义删掉只剩口号，与堆满段落一样损害理解。标题、主要内容、补充说明、来源应有明显字号和位置差异，避免每句话都加粗。

需要更多空间时，依次尝试：删除重复句、合并同义项、缩短标签、改成图解或表格、调整布局，最后再决定拆页。页数服从用户要求及叙事，不为了展示布局种类而增加章节页、结尾页或附录。

## 图解必须表达正确关系

连线是内容的一部分，不能只承担装饰作用。生成前确认源与目标，渲染后核对箭头尖端：

- 审批或授权应指向受控动作的执行条件，不能用图示暗示先执行再审批。
- 数据流、正常流程和失败反馈使用不同位置或样式，并配必要标签；不能仅凭颜色区分。
- 状态、证据是否充分和允许采取的动作是不同维度。若使用多个状态标签，应先定义它们的含义及关系。
- 反馈应落到下一步动作，例如补证据、修订、复验或转交负责人。仅记录日志不自动表示问题已经解决。
- 曲线或弧形连接可用后端支持的原生连接符或可编辑自定义路径。预设布局不支持所需关系时，选其他支持的结构；不要提供未实现的 plan 字段。

流程中需要暂停、授权、分支或循环时，应让观众看得到关键条件。详细执行机制可以放备注，无需把课堂或概念方案扩展成完整生产规范。

## 原生对象与插图

文字、表格、基础形状、箭头、流程节点保持可编辑。数值图表应使用原生图表对象并保留真实数据与单位，不制造装饰性统计数据。当前生成器的 12 种布局以文本、表格与关系图为主；不能据此假定它支持任意统计图表，也不要发明 `chart` 字段。确需未支持的数值图表时，使用宿主的原生图表工具，或用当前支持的可编辑表格准确呈现数据。

背景网格、黄渐变装饰和概念插图可以是图像。插图用于帮助理解对象或场景，不能替代关键文字、来源和流程关系；必要时标注“概念示意”。缩放保持比例，优先避免关键对象被裁掉；不要把整个幻灯片做成一张图片。

本包不负责自动生成图片。已有素材需有可用来源与授权；缺少插图时可以用简洁原生形状完成表达，不必引入额外模型服务。

## 局部修改与源文件保留

修改稿件时先确认哪些页面、内容或布局已被用户接受。沿用其叙事和样式，只改变请求涉及的区域，并输出新版本。尤其不要因为一次补充说明而重排全稿、替换整套视觉或新增许多页。

已有 plan 时修改对应页面字段，再检查生成后受到影响的页面。若只有 PPTX，使用宿主可用的 PPTX 编辑工具；本生成器不导入已有 PPTX。必要的重建应保留原文件，并明确重建范围。

追加信息时优先替换弱信息或缩短已有标签。例如把泛泛的“检查与调用”改为具体的“校验目标与授权”，比增加一段解释更有效。不要在用户未要求时将某次项目的成员、案例、页数或讲述分配固化到模板。

## 证据、备注与交付检查

备注说明本页的主要推理、依据、假设和限制，可附来源完整链接。页面可使用简短来源标题及有效超链接。未实测、概念示意、数据口径和会影响结论的限制应在页面可见；普通 PDF 不会包含备注。

事实、推断、提案和演示结果应能区分。不要将历史事实与设计示例混合，也不要将预期效果表述为已经完成的实验。来源必须对应具体主张，不使用看似真实但未经核实的链接。

逐页完整检查，而不是只看缩略图：

1. 中文字形、换行、孤字、溢出、裁切及内容是否落在安全区域。
2. 标题与正文的主次；浅底、深底及链接的实际对比度。
3. 箭头方向、回路、分支和对象归属；线条是否穿过文字。
4. 表格和数值图表是否可编辑，内容及单位是否正确。
5. 页数、备注、来源链接、署名及用户指定内容是否保留。

PPTX 生成成功只证明文件写出。若交付 PDF，单独检查分页、字体、连线和超链接；不同软件的渲染结果可能不同，说明实际使用的验证方式。
