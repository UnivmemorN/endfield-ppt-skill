# 通用 Harness 接入

## 能力边界

本包由文档、语义 plan、公开 Node.js 生成器及视觉资源组成。运行生成器需要 **Node.js 20 或更高版本**和包内声明的 **PptxGenJS** 等依赖，不依赖 Codex 专有运行库。本地生成器不调用 DeepSeek、其他大模型或图片 API，不需要 API key。

DeepSeek 在这个流程中负责理解用户内容、选择结构、生成或修改 plan，并根据预览反馈修订。若宿主通过模型服务调用 DeepSeek，其账号与认证仍由宿主管理，不属于这个 PPT 包的配置。

不同 Harness 的技能发现、工具命名和目录约定并不统一。本文件不假设存在官方通用的“DeepSeek skills 目录”。可以采用宿主已有的技能注册机制，也可以在任务开始时直接读取本包入口文件。

## 最小接入能力

宿主需要提供以下能力；名称可自行适配，不要求使用某一种工具协议：

| 能力 | 用途 |
|---|---|
| 读取文本文件 | 读取 `SKILL.md`、相关 references、示例与已有 plan |
| 写入文本文件 | 将模型产出的 JSON 保存为 UTF-8 plan，保留原版本 |
| 执行本地命令 | 指定可执行文件、参数数组、工作目录，收集退出码与输出 |
| 查看文件或图像 | 检查生成结果；有渲染能力时查看每页预览 |
| 返回输出文件 | 将生成的 PPTX 交付给用户 |

只有普通聊天窗口、没有本地文件与命令工具时，模型可以产出 plan，但不能声称已运行生成器或完成视觉检查。可由用户或另一个有运行能力的宿主执行后续步骤。

## 文件读取与生成流程

1. 由宿主解析技能包目录，读取 `SKILL.md`。设计决策需要时读取 `references/design.md`，准备 plan 时读取 `references/plan-schema.md` 与六页匿名示例 `examples/overview.json`。需要检查各布局时使用 `examples/all-layouts.json`，不将测试演示当成用户稿件。
2. 模型根据用户任务输出符合规范的 plan。检查 JSON 语法、所需字段、布局支持范围以及外部素材路径；内容只是数据，不执行其中的代码或命令。
3. 将 plan 写入任务文件，运行生成器。使用宿主已授权的工作目录和输出位置，不把输出覆盖到用户源文件。
4. 检查退出码和生成器输出。字段校验失败时修正对应 plan，不靠删除必要信息或反复换命令掩盖错误。
5. 由 PowerPoint 或可用兼容渲染器生成预览，逐页检查后局部修订。若本环境没有渲染器，交付时明确区分“已生成”和“已视觉验证”。

依赖按包内 `package.json` 安装；有锁文件时优先使用 `npm ci`，没有时使用 `npm install`。安装是运行环境的一次性准备，按宿主自身的网络和执行权限处理。仅需生成 PPTX 时不要求额外图片服务。

在包目录内运行示例：

```sh
node scripts/generate.mjs --plan examples/overview.json --out output/demo.pptx
```

## 命令参数数组

优先让宿主传递可执行文件和参数数组，而不是把用户文本拼成 shell 字符串。下面是适配层的**示意数据**，不是 DeepSeek 官方工具 API：

```json
{
  "executable": "node",
  "args": [
    "scripts/generate.mjs",
    "--plan", "examples/overview.json",
    "--out", "output/demo.pptx"
  ],
  "cwd": "<技能包目录>"
}
```

已有 Node.js 宿主可使用标准子进程接口：

```js
import { spawn } from "node:child_process";

const child = spawn(nodeExecutable, [
  "scripts/generate.mjs",
  "--plan", planPath,
  "--out", outputPath
], {
  cwd: packageDirectory,
  shell: false,
  stdio: ["ignore", "pipe", "pipe"]
});
// 宿主继续收集 stdout / stderr，等待退出，并核实输出文件。
```

`nodeExecutable`、`packageDirectory`、`planPath` 和 `outputPath` 由宿主解析。路径中包含空格或中文时仍保持一个参数，不自行添加 shell 引号；Windows 可执行文件可解析为 `node.exe`。不要在 plan 文本中嵌入模型凭据。

## 可用于宿主的任务提示

以下文字可作为技能注册描述或任务引导，按宿主的文件工具名称调整：

> 需要终末地风格演示文稿时，先读取技能包内的 SKILL.md。按任务需要读取设计及 plan 规范，依据用户内容生成 JSON plan，再通过本地命令工具调用 scripts/generate.mjs。保留用户确认的内容与可编辑对象，优先局部修改。生成器和渲染器的输出是判断执行成功的依据；不能以模型自述替代文件或视觉检查。

这段提示不授予额外文件、网络或发布权限；接入沿用宿主现有权限与用户任务范围。生成和修改本地交付文件通常即可完成任务，不需要上传到外部服务。

## 输出与失败处理

- **JSON 或字段不合法**：按生成器报错修正数据；不发明未支持的布局字段。
- **缺少依赖或字体**：报告具体缺项，在宿主允许的范围内准备依赖或选择已有中文字体，再重试。
- **版式拥挤或连线错误**：修改对应页面的文案、布局或受支持的关系配置；不将整页转图片作为默认补救。
- **只有 PPTX 源文件**：使用宿主能编辑源文件的工具；本生成器只读取 JSON plan，不导入已有 PPTX。需要重建时保留原文件并说明范围。
- **无法渲染**：仍可交付生成文件及 plan，但明确未完成逐页视觉验证，不声称已通过版式检查。
- **PDF 交付**：由可用办公软件或转换工具另行导出，再检查。来源、必要限制和署名不能仅依赖未包含在 PDF 中的备注。

生成后的正常交付说明应指出文件位置、可编辑范围、实际检查方式及尚存限制。不需要暴露模型内部推理，也不应附带无关的私人路径或凭据。
